# Personal Gantt

A small web app over the "Personal Gantt" Google Sheet: a day view with study hours, readings, tasks, calendar events and the next exam countdown, a scrollable timeline, exam cards, a grades log and a task list. Changes are written straight back to the sheet, and the whole plan is mirrored in a "Personal Gantt" Google calendar.

The site holds code only. The sheet and calendars are read in the browser after Google sign-in, so the data stays private even though the site is public.

## Setup

1. In Google Cloud, enable the **Google Sheets API** and the **Google Calendar API**, and create an OAuth client ID of type Web application, with `https://<github-user>.github.io` as an authorized JavaScript origin.
2. Put the client ID in `config.js`.
3. Publish with GitHub Pages from the `main` branch, root folder.

## Staying signed in

On its own, a sign-in made in the browser lasts an hour and needs a tap to renew. To keep the app signed in, the sheet's Apps Script (below) also works as a small web app that runs as you and hands the app a fresh Google token when it asks:

1. In the Apps Script editor, add the **Google Sheets API** under **Services (+)** (keep the name `Sheets`), next to the Calendar API.
2. **Deploy > New deployment**, type **Web app**, Execute as **Me**, Who has access **Anyone**, then **Deploy** and allow access.
3. In the sheet, **Personal Gantt > Connect the app**. It writes the web app address and a key to the Settings tab (`app_token_url`, `app_token_key`).
4. Open the app and sign in once on each device. From then on it signs itself in when opened and renews its token in the background, with no sign-in screen.

Every request must carry the key. Anyone holding it can read and change your sheets and calendars, so do not share the Settings tab. **Personal Gantt > Reset app access** replaces the key, which signs every device out until it signs in once more; **Sign out** in the app forgets the key on that device. After pasting a new `Code.gs`, the web app keeps running its deployed version; only changes to `doGet` need **Deploy > Manage deployments > Edit > New version**.

## The database

The **Items** tab is the single source of truth: one row per item, with columns found by their header names.

| Column | Meaning |
|---|---|
| id | Unique and never reused: a type letter and 6 characters, such as `t-4k9x2a` |
| type | `study`, `log`, `reading`, `task`, `exam`, `event`, `exercise` or `note`. Any other type still shows, under Other |
| area, subject, title | What the item is and where it belongs |
| date, end | `YYYY-MM-DD`; `end` only for multi-day items |
| time, minutes | `HH:MM` in Istanbul time, and duration |
| hours | Planned hours of a reading |
| days | Per-day values: planned hours (study), studied hours (log), sessions (exercise) or X marks (scattered task days), as `2026-10-27=2.5; 2026-10-28=1` |
| status, done_on, priority | `open` or `done`, the finish date, `P1` to `P3` |
| notes | Free text |
| calendar | `auto` (default): in the Personal Gantt calendar; `off`: left out |
| event_id, synced | No longer used (left from the earlier sync) |
| updated | Managed by the app |

The **Settings** tab holds the plan dates and the id of the Personal Gantt calendar. The **Gantt** tab is a formula view of Items, for reading in Google Sheets.

Writes are addressed by id: before each save the app reads the id column and finds each item's current row, so rows added or removed elsewhere (by hand, by Claude, or on another device) never receive another item's change.

## Calendar sync

The whole plan is mirrored in the **Personal Gantt** Google calendar:

- every task, reading, exam and event with a date: a timed event when it has a time, otherwise an all-day entry (finished tasks and readings are titled "Done: ...");
- one all-day entry per day of planned study, with the total and the hours per subject ("Study 5 h: Calculus I 3, Physics I 2");
- one all-day entry per exercise session (Workout A, Workout B, Light workout, Weigh-in);
- tasks planned on scattered days (X marks in `days`) get one entry per marked day.

Study logs are never exported, and a row whose `calendar` column is `off` is left out. All-day planning entries are marked free and have no notifications; timed items and exams keep the calendar's default reminders.

The rules live in one place, `js/gantt-export.js`, which runs in two places:

1. **The app**, after every load, so changes made in the app reach the calendar at once.
2. **An Apps Script attached to the sheet**, every 10 minutes, so changes made by Claude, by hand, or on another device reach the calendar without opening the app. `apps-script/Code.gs` is that script; it is generated by `node tools/build-apps-script.mjs` from `js/gantt-export.js` and `apps-script/sync.gs`. To install it: in the sheet, **Extensions > Apps Script**, replace the code with the contents of `apps-script/Code.gs`, save, add the **Google Calendar API** under **Services (+)** (keep the name `Calendar`), pick **setup** in the function menu, **Run**, and allow access. The sheet then also has a **Personal Gantt > Sync calendar now** menu. After changing the export rules, rebuild and paste the new `Code.gs` the same way (no need to run setup again).

The sync is stateless: each event carries the id of the row (or row and day) it mirrors, and a fingerprint of its content, as private extended properties. A run lists the calendar, inserts what is missing, updates what changed and deletes what no longer has a row (from `plan_start` on, at most 120 days back, so archived rows keep their past events). Events without these properties, for example ones added by hand, are never touched. The `event_id` and `synced` columns are no longer used.

Events in your other calendars (holiday calendars excluded) show read-only on the Day view and the Timeline; the Account sheet picks which.

## Reschedule flags

Any task, reading, event or exam, any day of planned study (from the subject's hours sheet, on the Day view or the Timeline), and any event from your other calendars on the Day view, can be flagged with **Reschedule later**, with an optional note such as "after midterms". Each flag is a row in the **Reschedule** tab:

| Column | Meaning |
|---|---|
| id | `r-` and 6 characters |
| kind | `item` (a row of Items), `study` (one day of a study row: `was` is that day) or `calendar` (an event in another calendar) |
| ref, cal_id | The item id, or the event id and its calendar id |
| title, was, note | What it is, when it was planned (`YYYY-MM-DD HH:MM`) and the note for the run |
| status | `pending`, then `done`, `skipped` or `cancelled` |
| flagged, handled | Timestamps |
| result, new_when | What the run did, and the new date and time |

The daily scheduled run moves every pending flag to a later date that fits (for `study`, it moves that day's planned hours in the row's `days` to a later day before the subject's exam), then marks it `done` with a one-line result, or `skipped` with the reason. The Tasks page lists pending flags and those handled in the last three days. Removing a flag sets it to `cancelled`.

## Grades

The **Grades** page logs grades per class. Each grade is a row in the **Grades** tab:

| Column | Meaning |
|---|---|
| id | `g-` and 6 characters |
| course | The class, such as `Calculus I` (matches the exam and study subject names) |
| name, kind | What was graded (`Midterm 1`), and its kind: `Midterm`, `Final`, `Quiz`, `Homework`, `Project`, `Lab` or `Other` |
| date | `YYYY-MM-DD` |
| score, out_of | The score and the maximum (100 if empty) |
| weight | Its share of the course grade, in percent, from the syllabus (optional) |
| exam_id | The exam row it was logged from, if any |
| notes, updated | Free text; managed by the app |

Each class shows its average out of 100: weighted by the grades that have a weight, with how much of the course those weights cover, or the plain mean when no grade has a weight. Exams finished in the last 60 days with no grade are listed under **To log**, and a finished exam card on the Exams page shows its grade or a **Log grade** button. Grades are not exported to the calendar. If the tab is missing, the app adds it with the first grade.

## Archive

**Archive past** on the Timeline moves every row that ended before today to the **Archive: Items** tab (same columns plus `archived_on`) and sets `plan_start` in Settings to today, so the app and the chart start from today. It asks for confirmation first. Kept in Items: open tasks and readings (they show as overdue), and the study plans and logs of subjects with an exam still ahead, since the exam cards need them. Past calendar events are left in place: the calendar clean-up only looks at events from `plan_start` onward. Archived rows can be copied back to Items by hand.

## Publishing an update

Raise the number in `version.json`, `BUILD` in `js/app.js` and the `?v=` values in `index.html` and the imports at the top of `js/app.js` and `js/calendar.js` together. Open copies of the app see the new number and reload themselves.
